### **Решение**
Расширяем архитектуру из Task3 компонентами для работы с кол-центрами.

**Основные компоненты:**
- **API для внутреннего кол-центра** - REST API на Java Spring Boot, интегрируется с их системой
- **SFTP Gateway** - отправка файлов партнерскому кол-центру
- **Сервис уведомлений** - мониторинг и алерты при проблемах

**Как это работает:**
1. Сервис ставок из Task3 получает новые данные
2. Автоматически отправляет обновления в кол-центр через REST API
3. Генерирует CSV-файл и отправляет партнеру по SFTP
4. Логирует все операции и уведомляет о проблемах

**Технологии:**
- Java Spring Boot для API (используем существующую экспертизу)
- SFTP с библиотекой JSch для передачи файлов
- CSV формат для партнера (их требование)
- Существующая база данных для логирования

**Почему такое решение:**
- Используем уже знакомые технологии
- Минимум изменений в существующих системах
- REST API быстрый и надежный для внутреннего кол-центра
- SFTP - единственный доступный вариант для партнера

### **Альтернативы**
1. **Email-рассылка файлов** - отклонили, потому что ненадежно
2. **Веб-портал для партнера** - они не готовы к такой интеграции
3. **Прямой доступ к базе ставок** - нарушает политику безопасности

**Недостатки, ограничения, риски**

**Недостатки:**
- Усложняется архитектура - больше компонентов для поддержки
- Нужно мониторить несколько каналов передачи данных
- Зависимость от стабильности SFTP-соединения

**Ограничения:**
- Партнер может получать только файлы, API им не подходит
- Кол-центры не видят персональные ставки клиентов
- Обновления не чаще раза в 5 минут

**Риски:**
- SFTP может падать - партнер останется без свежих данных
- Рассинхронизация между системами
- Нагрузка на сервис ставок при частых обновлениях
