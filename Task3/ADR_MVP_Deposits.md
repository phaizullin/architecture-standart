### **Решение**
**Концептуальная архитектура MVP:**

Решение основано на принципе минимальных изменений существующих систем с добавлением новых компонентов для обеспечения онлайн-функциональности.

**Ключевые архитектурные решения:**

1. **API Gateway** - новый компонент для разгрузки АБС и централизации API
2. **Сервис управления ставками** - замена Excel-процессов системным решением
3. **Интеграционная шина** - для связи между системами без прямого доступа к БД
4. **Кэширование** - для ускорения работы справочников

**Технологический стек:**
- API Gateway: .NET Core (совместимость с интернет-банком)
- Сервис ставок: Java Spring Boot (экспертиза команды АБС)
- База данных: MS SQL (для новых сервисов)
- Интеграция: REST API + очереди сообщений

**Логика принятия решений:**
- Сохранение существующих процессов бэк-офиса в MVP
- Использование знакомых технологий для быстрой разработки
- Минимизация изменений в критичных системах (АБС, интернет-банк)
- Подготовка к будущему масштабированию через API Gateway

### **Альтернативы**
1. **Прямая интеграция с АБС** - отклонена из-за рисков перегрузки БД
2. **Микросервисная архитектура с нуля** - отклонена из-за сложности и сроков MVP
3. **Полная автоматизация без бэк-офиса** - отклонена для MVP, планируется на второй фазе

**Недостатки, ограничения, риски**

**Недостатки:**
- Сохранение ручных процессов в бэк-офисе
- Дополнительная сложность архитектуры
- Необходимость синхронизации данных между системами

**Ограничения:**
- Невозможность изменения ядра интернет-банка
- Вертикальное масштабирование АБС
- Работа в рамках существующей инфраструктуры ЦОД

**Риски:**
- Производительность при росте нагрузки
- Сложность интеграции разнородных систем
- Зависимость от подрядчиков для критичных изменений
